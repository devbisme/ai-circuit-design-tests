## Notes
- **Jitter spec (≤5ps rms, the architecture's CP requirement) COULD NOT BE CONFIRMED.** The
  only datasheet obtainable for this exact MPN (`datasheets/SX3M20.000B10F20TNN.pdf`, from
  Shenzhen SCTF Elec) is a 2-page generic family catalog sheet ("0C/1C/2C/3C/5C/7C" series,
  1-160MHz) covering frequency range, supply, current, duty cycle, rise/fall time, and aging —
  **it contains no phase-noise or jitter specification at all**, part-specific or otherwise.
  A targeted web search for jitter/phase-noise data on this exact part number returned no
  manufacturer-specific results (only generic marketing claims of "≤0.3pS" for an unspecified
  low-jitter product line, not tied to this MPN). **This remains an open, unverified risk for
  the sample-clock design requirement** — carried forward unchanged from sourcing/architecture.
- No EasyEDA footprint on file at JLC (`has_easyeda_footprint:false`, confirmed) — the generic
  3225 4-pin oscillator footprint used (`Oscillator:Oscillator_SMD_Abracon_ASE-4Pin_3.2x2.5mm`)
  was not independently re-verified against a land-pattern drawing within this phase's budget
  (the available PDF is graphics-heavy and does not include a usable land-pattern page); this
  land-pattern risk is also carried forward unchanged.
- Symbol already matched (`Device:Crystal` — note: an oscillator like this is 4-pin active,
  not a passive 2-pin crystal; `sourced_bom.md` lists `Oscillator:Oscillator_SMD_Abracon...`
  as the footprint but `Device:Crystal` as the symbol, which is a 2-pin passive symbol — **flag
  for the coder**: a 4-pin active oscillator needs a 4-pin symbol (OE/GND/OUT/VDD), not the
  2-pin passive crystal symbol. This mismatch was not caught by sourcing and should be resolved
  before coding — either find/generate a proper 4-pin oscillator symbol or confirm SKiDL usage
  maps only 2 of the `Device:Crystal` symbol's pins and manually adds OE/VDD as extra pins.
