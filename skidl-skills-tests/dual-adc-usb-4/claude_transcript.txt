● Phase 1 is done. I made the requirement decisions myself as you asked; they're
  logged in SPEC.md. The main ones:

  - Inputs: BNC connectors (the only option that fits standard scope leads; SMA,
    banana and MCX ruled out). Input impedance is 1 MΩ ∥ ~20 pF, like a scope,
    so 10× probes can be compensated. DC coupled.
  - USB: it has to be USB 2.0 High-Speed. Both channels together produce 240
    Mb/s, and Full-Speed tops out at 12 Mb/s. Type-C connector.
  - Transfer mode: the board will always capture blocks into an on-board buffer
    of at least 16k samples per channel, then send them. Continuous streaming is
    only a goal: it needs 30–40 MB/s, which is about the practical limit of USB
    2.0, so it can't be promised on every host.
  - Power: USB only, at most 450 mA. No galvanic isolation, so the input ground
    is tied to the host's ground.

  The architecture phase is now running in the background. It will pick the ADC,
  the front-end supply topology, and the capture logic plus USB chip. I'll

● The architecture phase is done, and I've started part sourcing in the
  background.

  The architecture has 9 functional blocks, so the circuit code will be written
  one block at a time. It uses 17 ICs plus an oscillator. The alternatives the
  architect considered, and why each part won, are in
  architecture/ic_selection.md.

  - ADC: TI ADS5231, a dual 12-bit part. The architect reports it's the only
    dual 12-bit ADC stocked at JLCPCB, so I haven't checked that myself. It
    samples at 20 MSPS and the FPGA reduces that to 10 MSPS per channel, which
    makes the anti-alias filter easier.
  - Input chain: 1 MΩ divider (10:1) → OPA354 buffer on ±2.5 V → THS4521
    differential driver → ADC.
  - FPGA: Gowin GW1NR-9, which has built-in PSRAM for the capture buffer.
  - USB chip: FTDI FT232H in its synchronous FIFO mode, with a ceiling of about
    40 MB/s. Continuous streaming needs 30 MB/s, so it's best effort. The
    16k-sample-per-channel block capture is guaranteed.
  - Power: an LM27762 makes the ±2.5 V for the input amplifiers; every other
    rail comes from a linear regulator (LDO). Worst-case draw is about 364 mA
    against the 450 mA limit. The FPGA and FT232H figures are estimates, good to
    about ±30%.
  - Cost: about $86 per board at qty 10, under the $120 target.

  Things to know:
  - Single-source parts: the ADS5231 and GW1NR-9 each have only one supplier and
    low stock. That is the biggest sourcing risk.
  - FPGA programming: the JTAG pins run at 1.8 V, so the programming cable must
    follow the target voltage. A fixed 3.3 V cable would damage those pins.
  - Gain error: uncalibrated gain error can reach 3.5% worst case, against the
    2% target. It comes from the ADC's reference tolerance, and the software
    calibration the spec already assumes covers it.

  The options considered and the choice made at each decision point are in
  SPEC.md (requirements) and architecture/ic_selection.md (parts).

  Fixes made during the pipeline:
  - ADC reference capacitors: added the two 2.2 µF capacitors (C98, C99) that
    TI's reference circuit (Figure 21) shows and the architecture had left out.
  - FPGA boot straps: checked against Gowin's configuration guide (UG290).
    MODE0/MODE1 pull-downs changed from 4.7 kΩ to the recommended 1 kΩ, and a
    4.7 kΩ pull-up (R75) added on the DONE pin.
  - FT232H capacitor: moved the 4.7 µF bulk capacitor (C76) to the pin FTDI's
    reference circuit shows.
  - FPGA pins: a false warning about FPGA pins 68–88 was overruled, and the
    PSRAM bank and clock pins were confirmed, using Gowin's pinout documents
    (UG119, UG803).
  - Wrong symbols and footprints caught by the coders:
    - the ADC output resistor arrays would have shorted all the data lines
      together;
    - the BNC footprint in the parts list was for a dual connector;
    - the EEPROM symbol used the wrong package pinout;
    - the USB crystal symbol put one pin on a ground pad.

  Open risks:
  - Aliasing (medium, accepted by the architect): the anti-alias filter is only
    2nd order. Input content at 15–20 MHz is attenuated by just 14.5 dB and
    folds into the 0–5 MHz band. The cheapest fix is running the ADC at its 40
    MSPS maximum. Otherwise users must band-limit their signals, as with a
    scope.
  - Single-source parts: the ADC and FPGA each have one supplier with low stock,
    and only 615 of the BNC connector are in stock. Buy all prototype parts up
    front.
  - Clock jitter: the oscillator has no published jitter figure. The spec needs
    about 126 ps or better, which ordinary oscillators should meet easily, but
    measure it on the first board.
  - Continuous streaming: it needs 30 MB/s against a practical ceiling of about
    40 MB/s, so it may not work on every host. Block capture is guaranteed.
  - Hand-made footprints: the BNC and trimmer-capacitor footprints were
    generated, not taken from a library. Check them against the drawings before
    fabrication.

  For the gateware and firmware:
  - FPGA pin 72 must be configured as an input (the ADC drives it).
  - The FPGA's internal flash must be programmed first through the 1.8 V JTAG
    header. The programmer must follow the header's reference voltage; a fixed
    3.3 V cable would damage the FPGA.
  - The FT232H's EEPROM must be set up for 245 FIFO mode.

  SKiDL issues (for your repo):
  - In SKiDL 3.0.0, MPN= and LCSC= passed as Part() keywords never reach the
    netlist (I checked with a small test netlist). __main__.py has a workaround
    that copies them into the part fields.
  - gen_xml.py:67 loops over net.pins without sorting, so the order of lines in
    the BOM XML changes between runs.
  - The root node is created with an empty tag, which makes check_tags() log a
    false "Missing tag" warning.
